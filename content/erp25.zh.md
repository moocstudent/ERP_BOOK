## 核心讲义

### 角色 ≠ 部门

组织图上有「销售部」「财务部」,ERP 里却很少按部门授权——它按**角色(role / persona)**授权。

- 一个人可以挂多个角色:采购经理同时是「采购审批人」与「供应商主数据维护人」;
- 一个角色可以赋给很多人:全公司仓管员共用「仓库过账」角色包;
- **菜单与按钮跟着角色走**,不跟着花名册走。

所以本章说的「总经理视角」「CFO 视角」,指的是**登录后看到什么、被允许点什么、被要求关心什么数字**——不是行政头衔本身。

### 管理层不录单,却决定系统值不值得上

ERP 上线答辩时,业务骨干常问:「领导会用吗?」诚实的答案是:**领导几乎不录单据**,但他们必须**每天看例外**。

| 角色 | 典型动作 | 几乎从不做 |
| --- | --- | --- |
| CEO / 总经理 | 看驾驶舱、问红灯、拍板跨部门冲突 | 建采购订单、收货过账 |
| CFO / 财务总监 | 看现金与账龄、盯关账、批大额付款 | 逐笔录入发票 |
| 总账会计 | 复核自动分录、开关期间、对科目 | 替仓库补录收货 |

如果领导打开首页全是「待办录单」,说明角色配错了;如果首页全是绿、从无例外,说明 KPI 没接上真实单据——**驾驶舱必须能下钻到单据与责任人**,否则只是一张好看的图。

### CEO 驾驶舱:例外清单 > 漂亮报表

总经理关心的四类信号(上面沙盘可点开下钻):

1. **交付**:交期违约单数——连到销售订单与计划例外;
2. **盈利**:毛利率走势——连到产品组与价差科目;
3. **运营效率**:库存周转——连到积压物料;
4. **客户声音**:未关闭投诉/质量通知——连到质量模块。

CEO 的管理动作是:**打电话给责任人、要求解释、必要时改规则**(信用政策、安全库存、审批门槛)——不是亲自改单据。ERP 替她做的,是把「感觉公司有点乱」变成「12 张单、3 个责任人、一个根因模式」。

### CFO 视角:现金、风险、关账节奏

CFO 的首页更「短周期」:

- **可用现金** = 银行科目 − 已生成未执行的付款建议;
- **超期应收** = 账龄分析(E4)的红区,常联动信用冻结;
- **即将到期应付** = 已三单匹配可付 + 卡在匹配的发票(后者说明采购/仓库有未清事项);
- **月结进度** = 关账清单完成度(E7)——卡在哪一步一目了然。

CFO 很少自己点「过账」,但她决定:**哪个月能关、付款程序何时跑、信用政策松还是紧**。这些参数一改,全公司销售与采购的「能不能做」瞬间变化——这就是财务角色对业务的硬约束。

### 总账会计:业财一体的质检员

总账会计站在自动过账的出口:

1. **抽查今日业务抛转的分录**(收货、发货、报工)——金额异常要能沿单据流点回去;
2. **管理过账期间**:物流只能过本期,财务可过上期,特殊期间仅控制器——防倒签美化与迟到搅局;
3. **清理 GR/IR、待摊预提**等过渡科目——月结清不掉,报表不可信;
4. **仅有的手工凭证**:计提、重分类、汇兑——业务单据绝不回头手录。

她用 ERP 的方式与「记账软件会计」相反:**信任自动分录,审计例外**;而不是「业务做完了再补账」。

### 下钻:从红灯到责任人的最短路径

好的角色首页遵守同一交互:

```
KPI 红灯 → 明细列表 → 单张单据 → 单据流(前后参照) → 主数据 / 责任人
```

这条链断在任何一环,管理层就退回 Excel 与微信群——ERP 的「单一事实来源」价值随之蒸发。配置驾驶舱时,优先接**已有单据与现成报表**,而不是先画一张无法下钻的大屏。
