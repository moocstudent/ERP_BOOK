## 核心讲义

### ERP 不会自己长眼睛

工厂端若只靠办公室键盘录报工与收发货,系统里的进度、库存、成本会系统性滞后。**硬件是 ERP/MES 的神经末梢**:把物理世界的事件变成可过账的电信号与消息。

这与 **HARDWARE_BOOK** 的主线一致——传感器读世界、执行器/显示让世界看见、总线与 MCU 把信号送出去——只是工厂里把这些零件组装成了安灯、扫码枪、PLC 与边缘网关。

### 分区硬件图谱(请多记几类)

| 分区 | 常见硬件 | 典型写入 |
| --- | --- | --- |
| **产线** | 安灯灯塔/拉绳、工位平板/HMI、PLC/CNC、智能扭矩工具、IoT 振动/能耗 | 停机码、报工、设备利用率、强制质检点 |
| **仓储** | 手持/固定扫码、RFID 门、RF 枪、拣选灯、语音拣选、标签机 | 收发货、拣配确认、批次/序列标签 |
| **质检** | 检重秤、视觉/AOI、温湿度探头 | 合格判定、废品原因、环境超限 |
| **物流** | AGV/AMR、输送线光电计数 | 库内转移、线边配送完成 |
| **基础设施** | 边缘网关、工控机、考勤门禁、工业交换机/UPS | 协议转换、断网缓存、工时与身份 |

沙盘图鉴里点开每一张卡片,看「硬件形态 → 现场事件 → ERP/MES 单据 → HARDWARE_BOOK 桥」。

### 上线优先级(务实顺序)

**第一波(往往性价比最高)**:

1. 条码/二维码枪 + 标签打印机(让物料与单据可扫);
2. 工位平板或简易报工终端(结束「下班补单」);
3. 安灯(异常可见、停机可计量);
4. 稳定的无线/有线网络与边缘缓存。

**第二波**:PLC/OPC-UA 自动计件、RFID 门、拣选灯、检重与视觉。  
**第三波**:AGV 集群、全厂数字孪生大屏——没有前两波,大屏只是动画片。

### 与 HARDWARE_BOOK 的概念桥

| HARDWARE_BOOK | 工厂落地 |
| --- | --- |
| 传感器(光、温湿、称重、距离) | 扫码头、环境探头、检重秤、对射光电 |
| 执行器与显示(LED、蜂鸣、屏) | 安灯灯塔、拣选灯、HMI |
| 数字 I/O / 消抖 | 安灯拉绳、确认按钮 |
| MCU(Arduino/ESP/Pico 思想) | 边缘节点、协议网关 |
| UART / I²C / SPI | 升级为 RS-485/Modbus、CAN、EtherNet/IP、OPC-UA |

学硬件不是为了在工厂里焊洞洞板,而是为了**听懂现场集成商在说什么**,并判断一条链路会不会把脏信号写进总账。

### 没有硬件时的假 ERP 症状

- 库存「账实相符」只在月底盘点日成立;
- 工单进度靠班组长口头汇报;
- OEE 全绿但客户交期频频失约;
- 安灯亮了却不上系统——红灯只是气氛组。

## 练习

1. 为一家装配厂列出第一波 4 类硬件采购清单,并各写「不买的代价」。
2. 选 RFID 门与固定扫码头之一,说明更适合整托收货还是单件报工。
3. 用 HARDWARE_BOOK 词汇描述:安灯拉绳从按下到灯塔变红,信号可能经过哪些层。
