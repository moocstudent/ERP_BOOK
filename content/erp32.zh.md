## 核心讲义

### 安灯是状态机,不是气氛灯

丰田式安灯(Andon)的本质:**任何人发现异常都能立刻让产线状态可见,并强制组织响应**。硬件通常包括:

- **灯塔**(红/黄/绿或多段 LED);
- **拉绳 / 按钮 / 脚踏**(经消抖进入 MCU 或 PLC 输入);
- **工位屏 / 走廊大屏**(显示工位、原因、已等待分钟);
- **声光报警**(HARDWARE_BOOK 里的蜂鸣器与 LED 执行器放大版)。

没有写入系统的安灯,只是「亮了一下」。

### 推荐状态机

```
绿灯(生产) → 呼叫(红) → 班长响应(黄) → 处置完成关闭 → 绿灯
                 ↓ 超时
              升级到车间/计划/销售
```

关闭时**必须**带原因码(缺料、设备、质量、人员……)。原因码进入:

1. **停机工时** → OEE 的可用率;
2. **成本中心 / 内部订单** → 谁为停机买单;
3. **工单冻结** → 禁止在红灯期间虚报工(与 COL3 令牌纪律一致)。

### 升级阶梯与对外影响

| 级 | 触发 | 动作 |
| --- | --- | --- |
| L1 | 呼叫 | 班组到场 |
| L2 | 超过 N 分钟未关闭 | 车间主任 + 物料/维修 |
| L3 | 质量类或预计影响交期 | 计划改承诺;必要时更新客户门户里程碑 |

缺料安灯若只停在班组微信群,销售仍对客户承诺「按期」——五端进度板(COL2)上的工厂泳道会撒谎。

### 与 ERP/MES 的咬合点

- MES:实时记录呼叫/响应/关闭时间戳;
- ERP:接收汇总后的停机与工单状态(不一定要秒级,但**不能丢**);
- 禁止:红灯期间工位终端仍可点「完工 100」。
