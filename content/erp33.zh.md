## 核心讲义

### 一次采集,四层链路

```
硬件事件 → 边缘校验/缓存 → MES/ERP 事务 → 库存与成本账
```

沙盘里四段管道对应这四层。少任何一层都会在弱网或脏标签时出事故。上方 **采集→过账拓扑 SVG** 会随步进点亮节点,与管道同步。

### 自动识别手段怎么选

| 手段 | 擅长 | 不擅长 |
| --- | --- | --- |
| 一维/二维码 | 单件、单据、库位;成本低 | 批量整托无视线时 |
| RFID/UHF | 整托过门、不用对准 | 金属/液体环境、成本与冲突 |
| 视觉 | 外观缺陷、无标签场景 | 算力与光照要求高 |
| PLC 脉冲 | 高速计件、与设备同步 | 不懂业务单据上下文(需网关补单号) |

### 四条典型闭环

1. **扫码收货**:扫 PO → 扫标签 → 容差/质检校验 → 移动类型 101;
2. **扫码发料**:扫工单 → 扫组件+库位 → BOM/ATP 校验 → 发料进在制;
3. **计件报工**:脉冲或流转卡 → 工位确认 → 幂等键去重 → 工序确认+倒冲;
4. **循环盘点**:扫库位 → 实盘 → 超阈值审批 → 盘盈盘亏过账。

### 可靠性三件套

1. **校验**:单是否存在、数量是否在容差、库位是否允许该物料;
2. **幂等键**:同一枪同一标签在重试时不双倍过账(集成章讲过的同一纪律);
3. **断网队列**:边缘网关先落盘,网络恢复按序补传,并同步时钟。

### 再桥一次 HARDWARE_BOOK

扫码头本质是光电/成像传感 + 解码芯片 + UART/USB;PLC 数字量输入类似你在开发板上读的 GPIO;边缘网关做的事,就是把多种总线(类比 UART/I²C/SPI 的工业放大版)归一成对 ERP 友好的 HTTPS/消息队列。

**纪律相同**:先读对信号,再驱动「过账」这个最贵的执行器。

下一章 **HW4** 把这句话展开成可落地的协议栈:**设备之间常走 RS-485/Modbus,进 ERP 常走 MQTT 或 HTTPS**,中间网关负责翻译与幂等。

## 练习

1. 为「先扫后过账」设计幂等键字段(至少含设备号、标签号、时间窗)。
2. 说明 PLC 只有脉冲、没有工单号时,边缘层必须补上什么主数据。
3. 列出断网 30 分钟内允许缓存、禁止直接写入总账的两类事务。
