## 核心讲义

### 组织建模:上线前最重要的一次「翻译」

ERP 实施的第一个大工作坊,讨论的不是功能,而是:**你的公司在系统里长什么样?** 现实中的集团、分公司、事业部、厂区、仓库,要翻译成系统里一套固定的组织单元层级。这次翻译之所以关键,是因为:

- **每张单据都必须挂在组织单元上**:采购订单属于哪个工厂?分录记进哪个公司代码?
- **权限与报表沿组织切分**:苏州工厂的计划员看不到成都的库存,分公司报表按公司代码出;
- **上线后几乎改不动**:每个组织单元下挂着成千上万张历史单据,重构 = 迁移。

### 三个视角,一棵树

组织建模要同时满足三方的诉求,常用单元如下(叫法取 SAP 系,其他厂商同构):

**财务视角**

- **公司代码(company code)= 法人实体**。一个公司代码一套完整账:独立的资产负债表与利润表、独立报税。判断标准非常硬:**要不要独立对外出报表?要,就必须是公司代码**。
- 多个公司代码可共用一套**科目表**(集团合并的前提),再各自保留本地科目映射。

**物流视角**

- **工厂(plant)**:计划与库存的核心单元——MRP 按工厂跑,库存按工厂算,BOM 与工艺路线挂在工厂上。注意「工厂」不一定是制造场所,一个大型配送中心也建成工厂。
- **库存地点(storage location)**:工厂内的库存细分——原材料库、成品库、线边仓、退货库。数量在库存地点层面管理,价值通常在工厂层面核算。

**销售视角**

- **销售组织(sales org)**:对外销售的责任主体,挂在某个公司代码下(收入记谁的账)。
- **分销渠道(distribution channel)**:线上/线下/经销/直营——同一物料可按渠道给不同价。

### 一个典型建模案例

华成集团:两个法人(制造公司、贸易公司),制造公司有苏州、成都两厂,贸易公司只有仓库:

```
集团(合并报表)
├─ 公司代码 1000 华成制造
│    ├─ 工厂 1100 苏州厂(生产)── 库存地点:原料/成品/线边
│    └─ 工厂 1200 成都厂(生产)── 库存地点:原料/成品
└─ 公司代码 2000 华成贸易
     └─ 工厂 2100 上海配送中心(不生产)── 库存地点:成品/退货
```

关键推论:制造公司卖货给贸易公司,**不是转库,是公司间交易(intercompany)**——要开发票、确认收入、两边对账。很多集团把这步想成「调拨」,上线后发现税务过不去,返工代价巨大。

### 常见建模错误

| 错误 | 后果 |
| --- | --- |
| 把部门建成工厂 | 部门重组时组织树报废 |
| 法人边界建糊(两法人共用公司代码) | 无法独立报税,审计不过 |
| 库存地点建太细(每个货架一个) | 单据选择爆炸,账实难对 |
| 图省事只建一个工厂 | 两地库存混在一起,MRP 结果不可用 |

经验法则:**法人从严(法律说了算),工厂从实(物理与计划逻辑说了算),库存地点从简(够用就好)**。
