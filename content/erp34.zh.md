## 核心讲义

### 一句话先立住

**RS-485 / Modbus 解决「设备和设备怎么连」;MQTT / HTTPS 解决「事件怎么进 IT/ERP」。**  
中间必须有一台(或一排)**边缘网关**做翻译——ERP 从不直接「听」485 总线上的寄存器。

### 四层对接栈(请背下来)

```
┌─────────────────────────────────────────────┐
│ ④ ERP / MES 事务层                           │
│    报工、收货、停机码、库存移动、成本         │
│    入口: REST API / IDoc / 中间件适配器      │
├─────────────────────────────────────────────┤
│ ③ 消息 / 集成层                              │
│    MQTT Broker、Kafka、iPaaS、HTTPS 回调     │
│    主题/队列、QoS、重试、死信                │
├─────────────────────────────────────────────┤
│ ② 边缘网关层                                 │
│    协议转换 · 补主数据 · 校验 · 断网缓存     │
│    工业 PC / 软网关 / 采集盒                 │
├─────────────────────────────────────────────┤
│ ① 现场总线 / 设备层                          │
│    RS-485 + Modbus RTU、CAN、IO-Link…        │
│    仪表、PLC、安灯控制器、传感器节点         │
└─────────────────────────────────────────────┘
```

沙盘 `protoStack` 提供两种视图：

- **SVG 拓扑**：车间网（左）与 IT 网（右）分区；橙点报文沿当前层路径飞行（情景 A 可见 485 多从站总线 → 网关 → MQTT 扇出 MES/ERP）。
- **分层流程图**：四层栈横向展开，与下方可点选层卡片同步。

安灯 `andonBoard`、扫码 `scanToPost`、多端 `collabWorld` / 产线 `factoryTwin` 也都带平面拓扑 SVG，与 3D 或状态机对照阅读。

### ① 现场层:为什么是 RS-485 + Modbus

| 点 | 说明 |
| --- | --- |
| **RS-485** | 物理层:差分信号、可多点、抗干扰、百米级电缆——工厂配电柜旁常用 |
| **Modbus RTU** | 应用层:主站轮询从站,读保持寄存器/线圈(如「本班产量」「运行位」) |
| **不直接给 ERP** | 帧里只有地址+寄存器值,没有物料号、工单号、会计期间 |

对照 HARDWARE_BOOK:这像把 UART 做成多站差分总线,再约定一帧「读哪个寄存器」。

典型接线:

```
[温湿度]──┐
[电表]────┼── RS-485 总线 ──► [边缘网关 Modbus 主站]
[PLC]─────┘
```

### ② 边缘网关:翻译官在干什么

网关循环做四件事:

1. **轮询** Modbus:`读从站 3 寄存器 40001–40004`;
2. **映射**:寄存器值 + 工位配置表 → `{ wo: "WO-5521", op: "0020", good: 12 }`;
3. **校验**:工单是否下达、数量是否离谱、时钟是否同步;
4. **发布**:组装 JSON,`MQTT publish` 或 `HTTPS POST`,失败则进本地队列。

没有这一层,要么 ERP 被寄存器洪水打挂,要么现场断网时整条线「失忆」。

### ③ 消息层:MQTT 怎么对接 ERP

常见落地(与沙盘默认情景一致):

```
Topic:  plant/{plantId}/line/{lineId}/confirm
QoS:    1(至少一次)  →  所以 ERP 侧必须幂等
Retain: false        →  报工事件不要 retain
```

载荷示例:

```json
{
  "eventId": "gw01-20260724-153012-0007",
  "plant": "1000",
  "wo": "WO-5521",
  "op": "0020",
  "goodQty": 12,
  "scrapQty": 0,
  "hours": 0.8,
  "source": { "bus": "modbus-rtu", "slave": 3, "reg": 40001 },
  "ts": "2026-07-24T15:30:12+08:00"
}
```

**ERP 怎么接 MQTT?**

- 路径 A:ERP/MES 自带 MQTT 适配器,订阅后调内部「报工 BAPI/API」;
- 路径 B:中间件订阅 MQTT → 转 REST/IDoc 写入 ERP(更常见于传统套装);
- 路径 C:网关不发 MQTT,直接 `HTTPS POST /api/confirmations`(枪机/平板场景更常见)。

MQTT 擅长**大量、异步、弱网**;REST 擅长**一问一答、强校验即时返回**。工厂里两者经常并存。

### ④ ERP 事务层:订阅之后仍要过账纪律

收到消息 ≠ 已入账。ERP/适配器必须:

1. 用 `eventId` 做**幂等**(重复投递不双记);
2. 校验工单/物料主数据;
3. 调用标准事务(报工、101 收货、停机单…);
4. **回执**:成功 ACK;失败进死信并告警——不能静默丢。

这与 IMP2「电商/MES 集成」是同一套保命三件套:幂等、重试/死信、对账。

### 三种对照情景(沙盘可切换)

| 情景 | 现场侧 | 上云/IT 侧 | 典型用途 |
| --- | --- | --- | --- |
| **A 计件报工** | PLC↔网关 **RS-485/Modbus** | 网关→Broker **MQTT**→ERP | 高速产线自动报工 |
| **B 手持收货** | RF 枪 **USB/Wi-Fi HID 或专有协议** | 终端 App **HTTPS REST**→ERP | 仓库收发货 |
| **C 机床数据采集** | CNC **OPC-UA** | 网关→**MQTT** 或直接 OPC 桥 | 利用率、程序号、报警 |

注意:**OPC-UA 多在车间以太网**,不是 485;但「先现场协议、再网关、再 IT 消息」的分层不变。

### 反模式(项目里常见翻车)

1. 每个传感器直连公网 MQTT、绕过网关——安全与主数据映射双崩;
2. ERP 直接做 Modbus 主站轮询——把管理软件绑死在现场拓扑上;
3. MQTT QoS1 却不过幂等——弱网必双过账;
4. 把寄存器原始值当「业务完成」——没有工单上下文的产量只是噪声。

### 选型速查

| 需求 | 更偏向 |
| --- | --- |
| 柜内多仪表、长距离抗干扰 | RS-485 + Modbus RTU |
| 车间以太网、信息模型丰富 | OPC-UA |
| 云端/多订阅者/断续网络 | MQTT |
| 用户点一下要立刻成功/失败 | HTTPS REST |
| 系统很多、映射复杂 | MQTT/REST + iPaaS(见 IMP2) |
