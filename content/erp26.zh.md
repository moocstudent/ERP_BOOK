## 核心讲义

### 一线才是「每天在跑」的人

流程模块(E3–E6)讲单据怎么串;本章换鞋:销售、采购、计划、仓库、车间——**每人每天实际点哪些事务码 / 菜单**。ERP 若只给管理层做驾驶舱、一线仍用 Excel,上线等于没上。

五个角色对应三条闭环加库存:

| 角色 | 主闭环 | 一天里的「主单据」 |
| --- | --- | --- |
| 销售员 | O2C | 报价 → 销售订单 → 交货跟催 |
| 采购员 | P2P | 采购申请 → 采购订单 → 发票差异 |
| 计划员 | 计划到生产 | MRP 例外 → 计划订单下达 |
| 仓管员 | 库存 | 收货 / 发货 / 盘点 |
| 车间主任 | 制造执行 | 工单报工 → 完工入库 |

### 销售员的一天:承诺必须过系统

销售最容易犯的错不是「不会点」,而是**口头改承诺**:电话里答应改交期、加数量,系统里的销售订单不动——于是 ATP、信用、交货、开票全部基于旧事实。

健康节奏(对照沙盘时间轴):

1. 询价 → **报价单**(价格来自条件记录);
2. 确认 → **销售订单**(参照报价,少敲字段);
3. 保存瞬间:**ATP + 信用检查**自动跑——过不了就改交期或走特批,而不是硬存;
4. 客户变更 → **改单**(变更也是单据);
5. 临近交期 → 查未清交货,催仓库——**销售不自己过账扣库存**。

销售用 ERP 的核心能力是:**把对客户的每一句承诺写成可检查的单据状态**。

### 采购员的一天:从建议到合同到跟催

采购员的输入大量来自 MRP(计划申请),输出是有法律效力的采购订单:

1. 清理采购申请:合并、选源、转 PO;
2. 超金额走审批——**能建单 ≠ 能批单**;
3. 跟催逾期:供应商确认交期写回 PO,供 MRP 当「在途供给」;
4. 三单匹配价格失败时,**采购是价格差的第一责任人**(改 PO 或退票);
5. 看供应商评分——分数由收货/质检自动汇总,**采购改不了分数,只能改合作策略**。

采购角色的纪律:没有申请来源的「人情单」、无 PO 要求仓库收货——都是内控警报。

### 计划员的一天:翻译官,不是救火队长

计划员夹在销售承诺与车间产能之间:

- 早上读 **MRP 例外**(缺料、提前、推迟、取消建议);
- 把计划订单**下达**为生产工单或采购申请——下达才真正占资源;
- 与销售对齐:交不出的单是改承诺还是加急;
- 主数据或大单变化后**局部重跑**,避免抱着过期例外决策;
- 安全库存、提前期、批量规则是**策略参数**,不是「再多备一点」的随手改。

计划员用 ERP 最好的状态是:**例外清单越来越短**——说明主数据与销售行为在变好,而不是计划员越来越忙。

### 仓管员与车间主任:账实相符的最后一厘米

**仓管员**对数量负责、对价格不负责:

- 发货参照交货单扫码 → 库存与销货成本同秒更新;
- 收货参照 PO → 无 PO 收货在多数公司是红线;
- 工单发料 → 车间拿走必须过账;
- 循环盘点差异 → **先审批再过账**,禁止悄悄改库存数字。

**车间主任**让工单从纸变活:

- 不缺料才开工;
- 报工带合格数与工时 → 倒冲与成本归集;
- 停机用原因码,禁止虚报产量(否则效率差与标准成本全脏);
- 完工确认触发成品入库 → 计划看见供给、财务看见存货;
- 关单前说清量差/废品,否则成本中心背锅。

### 超级用户:上线后的翻译与灭火栓

每个部门应有 1–2 名**超级用户(super user)**:

- 会完整走本部门闭环,也懂上下游交接;
- 一线卡单时先找超级用户,而不是直接找顾问或 IT;
- 收集「真需求 vs 坏习惯」,参与权限与流程微调。

没有超级用户的上线,ERP 会在第三周退回微信群——因为没人能在业务语言与系统语言之间实时翻译。

### 一线最常踩的三个坑

1. **跳过参照**:不参照 PO 收货、不参照交货单开票——单据流断裂,审计与自动带数全废;
2. **事后补录**:先干活后补系统——账实窗口期里,ATP/MRP/财务全部在说谎;
3. **例外不处理**:MRP 例外、匹配失败、信用冻结当「系统又报错」忽略——问题滚成客户投诉。

## 练习

1. 选一个角色,写出其「禁止事项」清单(至少 4 条),并说明每条对应哪项内控风险。
2. 销售口头答应客户提前两天交货。分别写出:错误做法(不改系统)与正确做法(系统里动哪些单据)。
3. 为什么「计划员越来越忙」往往是主数据或销售行为的症状,而不是应给计划加人头的信号?
