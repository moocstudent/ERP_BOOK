## 核心讲义

### ATP:承诺之前先算账

销售最伤客户的行为是**答应了做不到**。可承诺量(Available-to-Promise)检查在接单瞬间回答:「这个数量、这个日期,我能不能承诺?」

基础公式(按时间轴逐期计算):

```
累计可用量(w) = 期初库存
             + Σ 计划流入(≤w)     ← 在途采购单、已下达生产单
             − Σ 已承诺需求(≤w)   ← 先来的销售订单
```

**关键细节:承诺量要取「该周及之后所有周的最小值」。** 因为库存是连续的:你在第 2 周答应发走的货,如果第 3 周有更早承诺的订单要用,就会把它挖走。沙盘里那个「W2 看着够、实际不能承诺」的例子,就是这个陷阱。

检查的时点:

- **下单时**:算出能承诺的日期写进计划行——可能是「要求日期全量」「推迟日期全量」或「分批承诺」;
- **改单/改计划时**:数量、日期一变就重算;
- **重排程(rescheduling)**:供给延误时批量重算所有受影响订单,按优先级重新分配——这是缺货时最考验规则的时刻。

### 缺货时的分配:先到先得?大客户优先?

ATP 天然是**先到先得**:早下的订单先锁库存。但现实中会叠加策略:

- **配额分配(allocation)**:新品/紧俏品按客户等级或区域切蛋糕,A 类客户保 70%;
- **部分交货(partial delivery)**:客户允许的话,先发可用的 150 台,余量下批——订单上有「最多几次分交、是否允许分交」的字段;
- **替代(substitution)**:同规格替代品、异地仓调货——ATP 可配置成「多工厂检查」。

### 信用管理:另一道闸门

交付风险之外还有**回款风险**。信用检查的公式:

```
信用暴露 = 应收账款余额        ← 已开票未收款
         + 未清订单金额        ← 已接单未发货
         + 已发货未开票金额
新订单放行条件:暴露 + 本单金额 ≤ 信用额度
```

超限的处理不是简单拒单,而是**冻结 + 例外流程**:订单挂起,信用管理员收到工作项,可以(a)要求预付款、(b)临时提额(需审批)、(c)等客户回款后放行。**发货前还会再查一次**——从接单到发货的几天里,客户的欠款可能恶化了。

信用额度怎么定?常见做法:客户上年采购额的 1/6(约两个月量)起步,按付款记录动态调整;新客户一律预付或货到付款,交易 6 个月后再评。

### ATP 的进阶形态

- **CTP(Capable-to-Promise)**:库存不够时继续往下算——「产能排得进吗?料买得及吗?」相当于为这张订单跑一次微型 MRP,给出「第 6 周可以」的答案;
- **全局 ATP**:多工厂、多仓库统一检查,就近分配;
- 电商场景的「库存扣减」本质就是简化版 ATP:下单锁定、超时释放。
