## 核心讲义

### 为什么要用「立体」看协同

流程图擅长画公司**内部**泳道;真实交付却发生在**五端同时在线**的网络里:

| 端 | 物理位置 | 在 ERP 中的典型身份 |
| --- | --- | --- |
| 供应商 | 外部园区 | 供应商主数据 · 采购订单 · ASN |
| 工厂 | 制造现场 | 工厂/车间 · 生产工单 · 报工 |
| 办公室 | 总部/共享中心 | 销售组织 · 公司代码 · 开票收款 |
| 仓库 | 物流节点 | 库存地点 · 交货/发货 |
| 客户 | 门店或产线旁 | 客户主数据 · 销售订单 · 门户进度 |

3D 场景不是为了炫技,而是逼你回答:**光点飞过时,哪张单据被创建或过账了?**——飞完一圈,你就理解了「多端协同」=「共享单据状态机」,而不是大家各自维护一张 Excel。

沙盘上方还有一张 **SVG 平面拓扑**:同一五端网络的 2D 投影,当前单据边高亮、橙点落在活跃链路上——与下方 Three.js 立体图对照阅读。

### 单据飞行 = 状态投影

上面沙盘里每一跳,都对应一条可审计的系统动作:

1. **客户 → 办公室**:销售订单(SO)+ ATP/信用;
2. **办公室 → 工厂**:计划下达生产工单;
3. **工厂 → 供应商**:缺料转采购订单(常经 EDI/门户);
4. **供应商 → 工厂**:ASN / 收货参照 PO;
5. **工厂 → 仓库**:完工入库;
6. **仓库 → 客户**:交货与发货过账;
7. **办公室 → 客户**:开票;
8. **客户 → 办公室**:付款核销。

伙伴往往**不登录你的 ERP**,但通过门户、EDI、API 写入的,仍是你库里的同一张单——否则又会裂成两个事实来源。

### 跨端等待:暗掉的那条路

协同断点几乎总是「一端以为做完了,另一端单据未到」:

- 供应商口头说已发货,ASN 未进系统 → 工厂 MRP 仍当缺料;
- 车间做完未报工 → 仓库看不到可发库存;
- 发货过了未开票 → 客户门户显示已收货,财务应收却是空的。

运营会议最有用的问题不是「大家加油」,而是:**指向沙盘里还没亮的那条边——卡在哪张单、谁是责任人?**

## 练习

1. 把沙盘 8 步写成一张表:步骤 / 单据 / 发起端 / 接收端 / 财务是否过账。
2. 若客户坚持「不要登录门户、只要邮件进度」,设计一种仍不破坏单一事实来源的做法。
3. 指出:仅做公司内部泳道、不画供应商与客户,会漏掉哪两类最常见的交期事故?
