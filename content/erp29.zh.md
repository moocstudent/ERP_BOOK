## 核心讲义

### 进度必须来自单据状态机

「完成 80%」如果靠人工填写,三周后没人信。可靠进度只有一种算法:

```
进度 = f(关键单据的系统状态)
```

例如 O2C 对外里程碑可以投影为:

| 客户可见 | 内部单据条件 |
| --- | --- |
| 已接单 | SO 已保存且信用通过 |
| 生产中 | 存在已下达且未完工的工单 |
| 已入库 | 成品收货过账完成 |
| 已发货 | 交货单发货过账完成 |
| 已开票 | 发票过账完成 |

内部五泳道可以更细(采购在途、质检、拣配),但**对外文案必须是内部状态的函数**,不能另起炉灶。

### 五泳道看板怎么用

沙盘里每条泳道回答四个问题:

1. **完成度 %** — 由该端相关单据算出;
2. **当前单据** — 一眼能点进去的单号;
3. **提示** — 下一步业务含义;
4. **是否阻塞** — 红灯必须有责任角色。

运营例会投这张板,比投一张无法下钻的「项目进度 PPT」有用一个数量级。

### 阻塞类型与升级

| 类型 | 典型单据信号 | 第一责任 |
| --- | --- | --- |
| 缺料 | 工单缺料 / PO 逾期 | 计划 + 采购 |
| 信用 | SO 信用冻结 | 信用专员 / 销售经理 |
| 质检 | 质检库存不放行 | 质量 |
| 匹配失败 | 发票校验差异 | 采购 / 应付 |
| 产能 | 工单排队过长 | 车间 / 计划 |

升级规则要写进 SLA:红灯超过 N 小时自动抄送下一级——规则在工作流里,不在群聊置顶。

### 诚实的 0%

缺料情景下仓库保持 0% **是正确的**:上游没货,仓库没有可拣的交货单。若强行把仓库刷成 50%「准备中」,客户门户与内部会议都会被骗。进度板的职业道德是:**宁可变红,不要假绿**。

## 练习

1. 为你的行业定义 5 个「客户可见里程碑」,各写一条内部单据条件。
2. 在「信用冻结」情景下,列出不应被触发的下游单据(至少 3 张)。
3. 设计一个红灯 SLA:谁在多少小时内必须响应,超时抄送谁。
