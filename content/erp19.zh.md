## 核心讲义

### 复式记账:五百年前的「区块链」

复式记账(double-entry bookkeeping)的公理只有一条:**每笔经济业务至少动两个科目,借方合计恒等于贷方合计**。会计恒等式是它的静态形式:

```
资产 = 负债 + 所有者权益
```

借贷方向的记忆法(别背口诀,理解方向):

| 科目类别 | 增加记 | 减少记 | 例 |
| --- | --- | --- | --- |
| 资产 | 借 | 贷 | 银行、存货、应收、设备 |
| 负债 | 贷 | 借 | 应付、借款、GR-IR |
| 所有者权益 | 贷 | 借 | 实收资本、留存收益 |
| 收入 | 贷 | 借 | 主营收入 |
| 费用/成本 | 借 | 贷 | 主营成本、工资、折旧 |

「借贷必相等」是内建的自检:任何一笔不平的分录,系统直接拒绝保存。错误可以发生(记错科目),但**不平衡不可能发生**——这就是它五百年不倒的原因。

### 科目表:财务数据的「目录树」

**科目表(chart of accounts)**是所有科目的编码清单,粗分两类:

- **资产负债表科目**:有余额、年末结转下年(银行 1002、应收 1122、存货 1405、应付 2202);
- **损益科目**:年末清零、结转进留存收益(收入 6001、成本 6401、管理费用 6602)。

明细靠**辅助核算**而不是科目膨胀:应收账款是一个统驭科目,按**客户**辅助核算;成本费用按**成本中心**辅助核算。科目表保持精干,维度交给辅助账——这是设计科目表的第一原则。

### 业务事件 → 分录:一条完整的故事线

把前面章节的自动分录串起来(金额示例):

| 事件 | 分录 |
| --- | --- |
| 采购收货 | 借 原材料 500 / 贷 GR-IR 500 |
| 发票校验 | 借 GR-IR 500 + 进项税 65 / 贷 应付 565 |
| 付款 | 借 应付 565 / 贷 银行 565 |
| 生产领料 | 借 生产成本 500 / 贷 原材料 500 |
| 完工入库 | 借 库存商品 900 / 贷 生产成本 900 |
| 销售发货 | 借 主营成本 900 / 贷 库存商品 900 |
| 销售开票 | 借 应收 1,356 / 贷 收入 1,200 + 销项税 156 |
| 客户回款 | 借 银行 1,356 / 贷 应收 1,356 |

读这张表的正确方式:**跟着「价值」走**——钱变成料,料变成在制品,在制品变成成品,成品变成成本与应收,应收变回钱。整条 P2P + 生产 + O2C 链,就是价值形态的八次转换。

### 科目确定:系统怎么知道记哪个科目

仓库工人过账收货时,没人问他「记哪个科目」——**科目确定(account determination)**规则替他决定:

```
科目 = f(移动类型, 物料的估价分类, 工厂/估价范围)
例:移动 101 × 估价分类 3000(原材料)→ 借 1403 原材料
    移动 101 × 估价分类 7920(成品)  → 借 1405 库存商品
```

这是一张实施时配置好的映射表。它的深意:**业务人员只做业务动作,会计规则被固化在配置里**——录入错误从「每个人都可能记错科目」收敛为「配置表对不对」一个问题。上线前财务顾问最重要的工作之一,就是把这张表配对、测全。

## 练习

1. 不看表,写出「收货 ¥2,000 原材料」「开票 ¥5,650(含 13% 税)」两笔分录。
2. 把八个事件的分录按「价值形态」画成一条链:钱→料→在制品→成品→成本/应收→钱,标出每次转换对应的事件。
3. 公司新增一类物料「包装材料」,希望单独核算。列出要改哪些配置(估价分类?科目?)与不该改哪些(移动类型)。
