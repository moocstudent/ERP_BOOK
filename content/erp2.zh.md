## 核心讲义

### 部门视角 vs 流程视角

传统的组织图是**纵向**的:销售部、采购部、生产部、财务部,各有各的领导、各有各的 KPI。但价值的产生是**横向**的:客户的一张订单,要依次穿过销售(接单)→ 计划(排产)→ 采购(买料)→ 仓库(收发)→ 车间(制造)→ 财务(开票收款)才能变成收入。

**流程(business process)**就是这条横向的价值链。管理学上一个经典的观察:大部分延误与错误,不发生在部门内部,而发生在**部门之间的交接处**——销售答应的交期计划不知道,仓库发的货财务不知道,这些「墙缝」正是 ERP 要填的地方。

### 泳道图:描述流程的标准语言

泳道图(swimlane diagram)每条「泳道」是一个角色/部门,每个方块是一个活动,箭头表示交接。读上面的沙盘时注意三件事:

1. **活动落在谁的泳道里**——责任一目了然;
2. **箭头跨越了几条泳道**——跨得越多,协调成本越高;
3. **每个活动对应什么系统动作**——ERP 里的流程不是画出来的,是被单据一步步「走」出来的。

### 单据流:流程在系统里的化身

ERP 用**单据(document)**记录流程的每一步。关键机制是**参照(reference)**:后一张单据引用前一张创建,数据自动带出。

```
销售订单 SO-10992
  └─ 参照创建 → 交货单 DN-80331(数量自动带出)
        └─ 参照创建 → 发货过账(库存自动扣减)
              └─ 参照创建 → 发票 INV-2301(价格自动带出)
```

参照链的三大好处:

- **少录入、少出错**:发票的价格来自订单,数量来自交货单,手工改不了;
- **全程可追溯**:从发票能一路点回原始订单(审计的最爱);
- **强制顺序**:没有交货就开不了票——流程纪律不靠自觉,靠系统。

### 三大核心闭环

| 闭环 | 走向 | 起点 → 终点 | 本课程模块 |
| --- | --- | --- | --- |
| **P2P** 采购到付款 | 钱流出 | 采购申请 → 付款 | E3 |
| **O2C** 订单到收款 | 钱流入 | 报价 → 收款 | E4 |
| **P2P(Plan-to-Produce)** 计划到生产 | 价值创造 | 需求计划 → 完工入库 | E5 |

三条闭环共享同一批主数据(E2),并且全部在财务(E7)汇合——每条闭环的每一步,都在往总账里自动写分录。

### 交接点 = 风险点

背下这张「流程断点排查表」,几乎能解释制造企业的大部分混乱:

| 交接 | 常见断点 |
| --- | --- |
| 销售 → 计划 | 答应了交不出的交期(没做 ATP) |
| 计划 → 采购 | 需求变了采购不知道(MRP 没重跑) |
| 采购 → 仓库 | 收货了不入账,账实两张皮 |
| 仓库 → 财务 | 发货了不开票,收入漏记 |
| 车间 → 财务 | 报工不及时,成本失真 |

## 练习

1. 选一个你经历过的流程(网购退货、报销、请假),画出它的泳道图:至少 3 条泳道、6 个活动。
2. 在你画的图上标出所有跨泳道箭头,写出每个交接点「如果掉链子会发生什么」。
3. 解释:为什么「开票必须参照交货单」比「财务凭责任心不多开票」更可靠?这体现了 ERP 三要素(流程×数据×规则)中的哪一个?
